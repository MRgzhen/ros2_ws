# G2 视觉识别抓取方案对比

> 整理日期：2026-09-20
> 机型：G2_t2v2_crsB（双臂 + 底盘 + 3DOF 头部云台）
> 目标：Gazebo 仿真中实现 相机识别 → MoveIt 规划 → 机械臂抓取 全流程

---

## 一、背景与目标

- 在 Gazebo 仿真环境中，用相机识别桌面上的物体，获取其位姿，交给 MoveIt 规划抓取
- 确定事项：**运行环境为 Gazebo 仿真**（非真机）
- 待定事项见文末「待定决策项」

## 二、仓库现状盘点

### 2.1 genie_robot_description（~/dev/G2_urdf）

| 项目 | 现状 | 对本任务的影响 |
|---|---|---|
| URDF/Xacro | ✅ 齐全，按机型+夹爪预生成（`urdf/G2_t2v2_crsB/`） | 可直接复用 |
| SRDF | ⚠️ 仅含碰撞矩阵（ACM，`<disable_collisions>`），**无规划组**（group/chain/virtual_joint） | 不能直接当 MoveIt SRDF，需补规划组 |
| 相机 | ⚠️ 仅 omnipicker 版有 2 个腕部相机 link（`gripper_l/r_camera_link`，挂在 `arm_l/r_end_link` 上）；**纯机械框架**：无 optical frame、无内参、无 `<sensor>` 标签 | 进 Gazebo 需自己加 sensor + optical frame，手眼关系需标定 |
| 头部 | 有 3DOF 云台结构（head_link1/2/3），未挂相机 | 可选在此加虚拟相机（眼在手外） |
| Gazebo | ❌ 无任何 `<gazebo>` 标签/插件、无 ros2_control | 仿真链路需从零搭建 |
| 感知代码 | ❌ 无 | 识别节点需新写 |
| 自带仿真 | MuJoCo（mjcf/），非 Gazebo | 与本次选型无关 |

注意：无夹爪版 `G2_t2v2_crsB.urdf` 没有相机；dahuan 等二指夹爪版也没有相机——**腕部相机是 omnipicker 灵巧手自带的**。

## 三、三大识别技术方案对比

| | ① 滑窗+SIFT/HOG+SVM | ② 点云几何管线 | ③ 深度学习检测 |
|---|---|---|---|
| **路线** | 传统 2D、手工特征 | 传统 3D、纯几何（无学习） | 学习法（CNN 自动提特征） |
| **输入** | RGB | RGB-D 点云 | RGB |
| **流程** | 滑动窗口遍历 → SIFT/HOG 特征 → SVM 分类 | RANSAC 平面分割（去桌面）→ 欧式聚类（分物体）→ 法线/曲率/RSD 特征 → 3D→2D 投影 → RANSAC 直线/圆拟合 + Hough 投票 → 拟合圆柱/长方体 | 一阶段：特征图上直接回归边界框+类别（YOLO，快、可实时）；两阶段：先生成候选区域再分类回归（Faster R-CNN，准、慢） |
| **输出** | 2D 分类结果 | **6DOF 形状 + 位姿** | 2D 边界框 + 类别 |
| **对抓取的适配** | 弱，无深度，需另配 3D 定位 | **强，输出可直接喂 MoveIt** | 中，需再融合点云反投影求 3D 位姿 |
| **训练数据** | 需要标注样本 | **零训练** | 需大量标注数据 |
| **速度** | 慢（滑窗遍历） | 中 | 一阶段快 / 两阶段慢 |
| **现状** | 已被深度学习取代，仅历史参考 | 经典桌面抓取管线，工程上仍常用 | 当前主流 |

## 四、方案之间的关系

1. **① → ③ 是历史演化关系**：滑窗+手工特征+SVM 这条路已被 CNN 检测器取代（③中的一阶段/两阶段就是演化产物）
2. **② 与 ①/③ 正交互补**：② 不回答"是什么"（类别），只回答"在哪、什么形状"；靠几何先验，与是否用学习法无关
3. **实际系统常组合使用**：③ 负责认物体（是什么），②/深度负责定位抓取（在哪、怎么抓）——如 GraspNet、YOLO+点云融合都是这个思路

## 五、简化选项与三大方案的映射

| 简化选项 | 对应关系 | 说明 |
|---|---|---|
| **颜色分割** | = 方案②的极简版 | 只保留"分割+定位"（HSV 阈值分物体、算质心），去掉法线估计和形状拟合；仿真里物体纯色时够用 |
| **AprilTag** | = 三方案之外的旁路 | 不识别物体本身，贴标签码直接解 6DOF 位姿；最稳、验证抓取规划最快，但物体必须贴码 |
| **YOLO** | = 方案③的一阶段 | 直接回归框，速度快 |

## 六、Gazebo 仿真下的适配性分析

| 方案 | 仿真适配性 |
|---|---|
| ② 点云几何管线 | **最好**——仿真深度数据完美无噪声，RANSAC/聚类/拟合效果理想，且零训练 |
| 颜色分割 | **最快跑通**——纯色物体+简单背景下 HSV 分割极稳，代码量最小 |
| AprilTag | 验证 MoveIt 抓取规划本身最快最稳，但需要给物体加 tag 贴图 |
| ③ YOLO | 性价比低——仿真场景简单，标注+训练成本高；练工程能力可选 |

**推荐路径**：先用颜色分割（或 AprilTag）跑通"识别→规划→抓取"全流程，再升级为完整方案②的点云几何管线输出 6DOF 位姿给 MoveIt。

## 八、无论选哪条路线都需要的基建（在 g2bot_* 包中实施）

1. `g2bot_gazebo`：机器人 spawn + ros2_control（arm/gripper 控制器配置）
2. 相机 sensor：在选定位置加 `<sensor type="rgbd_camera">` + optical frame + 相应话题
3. `g2bot_moveit_config`：基于预生成 URDF 补全 SRDF 规划组（arm chain 至 `arm_[l|r]_end_link`、gripper 组），可复用仓库现成 ACM（`srdf/G2_t2v2_crsB/*.srdf`）加速自碰撞检测
4. 桌面场景：桌面 + 待抓物体（纯色方块/圆柱或贴 AprilTag 的物体）
5. 识别节点 + 抓取执行节点（桥接识别输出 → MoveIt `computeCartesianPath` / `plan+execute`）
